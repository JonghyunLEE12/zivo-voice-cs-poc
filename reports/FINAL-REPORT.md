# 외국인 음성 상담 PoC 최종 보고서

작성일: 2026-10-30. M4 Pro / 통합 메모리 48GB / macOS 27.0.1에서 로컬 모델만 사용했다. 네 TTS 엔진, 정규화, Whisper, Ollama, 상담 화면, 블라인드 평가 및 리포트 경로를 구현했다. **실시간 데모 기본은 Kokoro가 적합하지만, 1.5초 답변 목표와 상담 도구 선택의 신뢰도는 달성하지 못했다. weak 병목 회피가 품질 향상의 원인이라는 가설은 이 실험만으로 입증되지 않았다.**

## 1. 실험 범위와 해석 기준

- 구조 가설은 B1 토크나이저 학습 언어 분포, B2 이산화 손실, B3 영어 중심 semantic teacher의 세 가지다. 구조별 판정은 [설계 1.3](../docs/DESIGN.md)의 조사 결과를 그대로 유지했다. 학습 데이터가 공개되지 않은 항목을 발음 점수로 추정하지 않았다.
- TTS 벤치는 Ollama를 내리고 엔진 하나씩 실행했다. RTF는 합성 시간/오디오 길이이며 작을수록 빠르다. 기본 세 엔진은 문장별 3회, CosyVoice3는 승인된 full 1회 축소 측정이다. 스트리밍 TTFA와 문장 전체 합성 TTFA는 반환 방식이 다르다. [T7/T8](T7-T8-REPORT.md)
- 클로닝 세 엔진은 언어별 같은 FLEURS 테스트 발화와 전사를 사용했다. Kokoro는 프리셋 화자라 화자 차이를 통제하지 못했다. **대만 억양 참조 없음**: zh-TW는 cmn_hans_cn 참조를 공유한다. [참조 매니페스트](../data/refs/MANIFEST.json), [T7/T8](T7-T8-REPORT.md)
- CER/WER는 Whisper 재인식 보조 점수다. 소문자·문장부호·숫자/코드 역정규화, 중국어 t2s를 적용하고 display_text와 비교했다. 사전 prompt 편향, 지명의 동음 한자 전사, 일본어 가나 변환 오류가 남는다. 원어민 청취 점수와 동일하지 않다. [벤치 상세](bench-20261030.md)

### 발음 오류율

full 결과의 문장별 오류율 평균. 영어는 WER, 나머지는 CER이며 낮을수록 좋다. 숫자는 [T7/T8 보고서](T7-T8-REPORT.md)에서 그대로 인용했다.

| 엔진 | en WER | zh-CN CER | zh-TW CER | ja CER | yue CER |
|---|---:|---:|---:|---:|---:|
| Kokoro | 6.2% | 4.7% | 5.7% | 10.0% | 미지원 |
| Qwen3-TTS | 8.7% | 2.1% | 7.2% | 7.0% | 미지원 |
| VoxCPM2 | 7.9% | 1.2% | 3.4% | 7.3% | 24.4% |
| CosyVoice3, 축소 | 9.5% | 2.4% | 3.4% | 44.9% | 37.3% |

일본어 full 가나 CER는 VoxCPM2 0.088, Qwen3-TTS 0.092, CosyVoice3 0.431이다. 표기 CER와 순위가 달라질 수 있다. 모든 엔진·언어의 raw/full·가나·고유명사·실패율은 [벤치 상세](bench-20261030.md)에 있으며, 선택 Qwen3-ASR은 미설치로 교차 채점하지 않았다.

영어 고유명사 적중은 Vox raw 6/9 → full 9/9, Qwen 8/9 → 9/9, Kokoro 9/9 → 9/9였다. 반면 일본어의 엄격한 display/aliases 적중은 Vox 5/6 → 2/6, Kokoro 6/6 → 2/6, Qwen 3/6 → 3/6이었다. Whisper의 동음 전사와 실제 발음 오류를 구분할 청취 평가가 필요하다. 정규화가 모든 언어에서 무조건 유리하다는 결론도 내리지 않는다. [T7/T8](T7-T8-REPORT.md)

### 속도와 메모리

언어별 full RTF 중앙값과 TTFA 중앙값 범위, 전체 보존 행의 최대 관측 메모리다. [T7/T8](T7-T8-REPORT.md)의 수치를 그대로 인용했다.

| 엔진 | en RTF | zh-CN | zh-TW | ja | yue | TTFA ms | 최대 관측 메모리 |
|---|---:|---:|---:|---:|---:|---|---:|
| Kokoro | 0.045 | 0.044 | 0.044 | 0.043 | 미지원 | 268~324, 문장 전체 | 2.65GB |
| Qwen3-TTS | 0.580 | 0.569 | 0.569 | 0.584 | 미지원 | 299~341, 스트리밍 | 8.96GB |
| VoxCPM2 | 1.794 | 1.753 | 1.805 | 1.799 | 1.800 | 9,240~11,229, 문장 전체 | 9.02GB |
| CosyVoice3 | 2.634 | 2.300 | 2.213 | 2.534 | 2.829 | 3,752~4,554, 스트리밍 | 13.89GB |

엔진 초기화/모델 로드 보고값은 Kokoro 1,194ms, Qwen 4,083ms, Vox 2,721ms, Cosy 10,264ms였다. HTTP supervisor 시작은 제외한다. 메모리는 RSS와 backend allocation 중 큰 값으로 둘을 더하지 않았고, Cosy 재사용 행에는 긴 배치의 누적 high-watermark가 남아 있다. 전체 시스템 RAM이나 동시에 실행 가능한 모델 수를 뜻하지 않는다. [T7/T8](T7-T8-REPORT.md)

Kokoro와 Qwen은 단독 합성 RTF가 1 미만이지만 전체 상담 지연은 STT·LLM·문장 확정·TTS가 합쳐진다. Vox와 Cosy는 이번 Mac 경로에서 RTF가 1보다 커 사전 합성·청취 비교에 더 적합하다. 초기 스모크와 벤치 조건은 다르므로 [MLX 엔진 보고서](../engines/mlx_engines/REPORT.md), [CosyVoice3 보고서](../engines/cosyvoice3/REPORT.md)의 단일 요청 수치를 위 표와 혼합하지 않았다.

## 3. 실시간 상담 결과

### 실제 Chrome의 첫 재생

Whisper + 기존 Ollama qwen3.5:35b-a3b + Kokoro/full, warmed 모델, 각 언어 1회다. 개발용 WAV 입력을 Chrome에서 Web Audio로 재생했으며 마이크 VAD는 우회했다. 이번 답변에는 filler가 없어 첫 음성과 첫 답변이 같다. 모든 수치는 [T10 보고서](T10-REPORT.md) 그대로이며 단위는 ms다.

| 언어 | STT | LLM TTFT | 문장 확정 | TTS TTFA | 첫 재생 − VAD 끝 |
|---|---:|---:|---:|---:|---:|
| en | 708.1 | 1114.3 | 514.2 | 601.7 | 2971.9 |
| zh-CN | 823.7 | 2613.9 | 375.8 | 841.3 | 4681.9 |
| zh-TW | 780.3 | 3047.4 | 816.9 | 672.3 | 5361.6 |
| ja | 753.6 | 2545.0 | 185.8 | 482.3 | 4001.3 |

**1.5초 목표는 미달이다.** T6.1은 늦은 도구 호출의 사전 발화를 막기 위해 tool-capable 라운드를 done까지 보류한다. 최종 LLM 전후 검증의 수정 후 첫 토큰 중앙값은 1,571.8ms, 첫 문장은 2,410.2ms였다. 안전한 도구/대화 상태 보존과 응답 속도의 절충이 남았다. [T6.1](T6.1-REPORT.md)

### Barge-in과 도구

- 서버 실제 WAV 검증의 barge-in ACK는 en 2.209ms, zh-CN 1.310ms, zh-TW 1.795ms, ja 1.727ms로 200ms 기준을 통과했다. en/zh-TW는 안내음 중, 나머지는 답변 시작 중 취소했다. ACK가 GPU 추론 종료나 스피커의 물리적 잔향 종료를 뜻하지 않는다. [T9](T9-REPORT.md)
- Chrome stub에서 재생 노드 중단은 performance.now 해상도 내 0.0ms로 100ms 기준을 통과했다. 이는 실제 사람의 끼어들기·에코 오탐률 평가가 아니다. 실제 Silero VAD 정상 입력은 별도로 검증했다. [T10](T10-REPORT.md)
- 실제 예약 WAV 조회 성공은 **2/4**였다. 영어와 대만은 조회 도구를 실행했지만 본토 중국어의 `ZV`가 `CV7305`로, 일본어의 `名字は佐藤`가 `領事は佐藤`로 전사되어 나머지 두 턴은 도구를 호출하지 않았다. 도구 시간 null을 성공으로 채우지 않았다. [T9](T9-REPORT.md)
- 최종 텍스트 상담 품질은 기본 **13/16**, 변형 포함 **39/48**, 다회차 **8/20**이다. 이는 도구 선택·응답 내용 등을 포함한 시나리오 성공 수이며 도구 HTTP 성공률이 아니다. 초기 T6의 16/16 및 5/5 통과보다 엄격한 최종 검사를 우선한다. 상담원 전환 및 다회차 도구 누락이 남았다. [T6.1](T6.1-REPORT.md), [초기 T2/T6](T2-T6-REPORT.md)

STT 초기 smoke는 FLEURS 5/5, say 명시 언어 4/4에서 비어 있지 않은 전사를 만들었고, 자동 감지는 4/4·확률 0.9981~0.9992였다. 동시 작업/첫 모델 로드를 포함한 기능 검증으로, 정확한 예약번호·이름 인식이나 격리된 지연을 보증하지 않는다. [STT 보고서](stt/REPORT.md)

### Smart Turn과 통화 지표

T11은 기존 8,679,182-byte Smart Turn v3.2 CPU를 적용했다. 실제 4언어 ON/OFF 8턴 및 취소 1턴을 완료했다. 중국어 두 입력은 미완료로 판정해 약 1.5초 대기했고, 첫 ON 영어는 lazy 초기화 비용을 포함해 턴 결정 2454.8ms였다. 이후 일본어 완료 판정은 47.5ms였다. ON이 항상 뒤에 있어 LLM 캐시가 유리하므로 전체 지연 차이를 Smart Turn의 개선 효과로 해석할 수 없다. [T11 비교 표](T11-REPORT.md)

T11의 종료 콜 9개에서 3분 이상 0/9, 끼어들기 발생 1/9, 콜당 고객 33.2자, 턴 9개, 상담원 전환 0개였다. 첫 오디오 가상 ACK p50/p90은 2214.2/4059.0ms, 답변 ACK는 4167.2/5502.2ms였다. **가상 재생 ACK의 짧은 연결이며 자연 고객 인게이지먼트나 T10 브라우저 지연과 비교하지 않는다.** 세션 정의·원자료·소표본 경고는 `/report`와 [T11](T11-REPORT.md)에 있다.

## 4. 블라인드 검증과 남은 한계

블라인드 full WAV 134개와 익명 비교 페이지를 준비했다. 자동화 fixture 10표의 저장·집계·방향 보정은 검증했지만 **운영 사람 평가 0표**이며 원어민 자연스러움/대만 억양 선호도는 미수집이다. 테스트 표로 선호도 결론을 만들지 않았다. [T7/T8](T7-T8-REPORT.md)

실서비스 판단 전에 남은 핵심 한계는 다음과 같다.

1. **LLM 도구 누락**: 상담원 요청·예외·다회차 슬롯 보충에서 실패한다. 가짜 DB/전환 큐만 쓰므로 실제 예약 시스템의 권한·중복 실행·취소·전환 부작용은 검증하지 않았다.
2. **STT 예약번호와 이름**: 코드 접두사·일본어 성 문맥 인식 오류가 실제 조회 실패로 이어진다. 사용자가 화면이나 DTMF로 확인할 경로가 필요하다.
3. **1.5초 목표 미달**: LLM TTFT, 라운드 보류, 비스트리밍 TTS가 영향을 준다. 캐시 안내음을 빨리 재생해도 실제 답변 지연과 구분해야 한다.
4. **대만 억양 미평가**: 본토 참조 공유와 Kokoro 간체 G2P는 대만 발음의 증거가 아니다. 번체 문자 준수도 억양과 별개다.
5. **원어민 청취 평가 미수집**: Whisper 오류율과 고유명사 hit는 보조 지표다. 광둥어·Cosy 일본어 오류, 정규화 전후의 한자/가나 차이는 원본 WAV 청취로 확인해야 한다.
6. **소표본·통제 부족**: 실시간은 Kokoro 한 조합이며 자연 발화, 장시간 다회차, 실제 고객·통신망·스피커 에코를 평가하지 않았다. Cosy 축소 표본, 화자/크기/학습 데이터 차이 때문에 구조 병목의 인과적 검증도 남는다.

근거: [T6.1](T6.1-REPORT.md), [T9](T9-REPORT.md), [T10](T10-REPORT.md), [T7/T8](T7-T8-REPORT.md), [T11](T11-REPORT.md).

## 5. 실서비스 전환 권고와 다음 실험

**로컬 유지**는 데이터가 장치를 벗어나지 않는 검증과 비용 통제에 적합하다. 이번 장치에서는 Kokoro로 상담 기능을 검증하고, 음질/클로닝 후보는 Qwen3-TTS와 VoxCPM2의 사전 합성 블라인드 비교로 좁히는 것을 권고한다. CosyVoice3는 현재 Mac 속도와 일본어 청취 확인 전 실시간 기본값으로 선정하지 않는다. 이는 위 실측에 근거한 PoC 범위의 판단이다.

**API 대안**은 같은 질의·음성·언어·도구 시나리오로 실제 네트워크 지연, 정확한 도구 선택, 동시 통화당 비용, 개인정보 보관/지역을 확인하는 별도 비교 실험으로 다룬다. 이번에는 유료 API·키를 사용하지 않았으므로 어떤 API가 더 빠르거나 저렴하다고 결론 내리지 않는다. 국내외 실서비스 적용 법률·계약·현재 가격 판단은 이 보고서의 측정 범위 밖이다.

다음 실험 순서는 다음과 같다.

1. 상담원 요청과 정책 예외를 서버 정책으로 확실히 연결하고, 슬롯 확인·권한 검증·도구 실행/재시도의 멱등성을 먼저 정한다. T6.1의 실패 발화를 고정 회귀 세트로 유지한다.
2. 코드/성의 확인 질문과 화면·DTMF 입력을 추가한 뒤 자연 발화로 STT 정확도를 재측정한다. 필요 시 선택 Qwen3-ASR을 동일 음성의 교차 채점용으로 별도 평가한다.
3. LLM 라운드 축소·작은 로컬 모델 또는 API 대안을 동일 품질 통과 표본끼리 비교한다. 새 모델은 별도 승인·메모리 예산 확인 후 받는다. first raw token, first valid sentence, filler, first reply를 분리한다.
4. Smart Turn은 중간 침묵·미완성 문장·실제 발화 종료 정답이 있는 데이터로 ON/OFF 순서를 무작위화하고 충분히 워밍업한다. 잘못 끊기/불필요 대기/에코 중단을 측정한다.
5. 대만 화자 참조·원어민 평가자를 확보하고 장치/화자/라우드니스를 통제한 블라인드 청취를 수집한다. 그 뒤 장시간 실통화에서 토스와 같은 콜 단위 지표를 비교한다.

## 6. 실행과 산출물

[README](../README.md)에 새 터미널 환경 준비, 다운로드, 포트, 엔진 하나와 메인 서버 실행, 상담/WAV 입력, 블라인드 생성/평가, 벤치와 세션 리포트 재생성 명령을 정리했다. [설계 1.4·7장·11장](../docs/DESIGN.md)은 선정 엔진 실측과 확인/미확인 항목을 반영했고, 비선정 모델의 수치를 만들지 않았다.

T11/T12의 완료 기준별 명령, 실제 결과, 자원 가드 및 변경 파일은 [T11 보고서](T11-REPORT.md)에 있다. 최신 벤치 원본은 [bench-20261030.json](bench-20261030.json), 통화 원본은 [T11 비교 JSON](t11/live/turn-comparison.json), 세션 export는 [session-metrics.json](session-metrics.json)이다. 자연 고객의 품질·억양·안정성 검증을 완료했다는 의미로 PoC의 기능 완료를 사용하지 않는다.
